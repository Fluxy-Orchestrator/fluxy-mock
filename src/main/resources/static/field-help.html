Trigger

Define cómo se activa el mock.

HTTP: responde a requests del proxy.

EVENT: responde a eventos consumidos desde una cola o bus.

HTTP: usa el endpoint /fluxy/mock/users/42
EVENT: consume sqs:fluxy-mock-queue y publica en SQS/KAFKA

Mode

Define qué hace la respuesta del mock.

STATIC_JSON: devuelve un body fijo
PROXY: reenvía la request al servicio real
CAPTURE: guarda la primera respuesta upstream
SECURE_CAPTURE: captura solo respuestas 2xx

Ejemplo: usar PROXY cuando todavía no querés stubear el payload.

Path pattern

Ruta que matchea la request o evento.

/users/{id}
/orders/{orderId}/items/{itemId}

Ejemplo: /users/{id} permite usar {{path.id}} en el template.

Target base URL

Base URL del servicio real cuando el mock actúa como proxy o captura.

https://api.example.com
http://localhost:3000

Ejemplo: en modo PROXY, la request se reenvía a esta URL.

Nombre

Etiqueta visible en la lista de mocks.

Ejemplo: Get User by ID, Create Order.

Enabled

Activa o desactiva el mock sin borrarlo.

Ejemplo: desactivarlo para dejar pasar tráfico real mientras ajustás respuestas.

Response JSON field overrides

Permite sobrescribir campos del JSON de respuesta con templates.

{"user.status": "\"active\""}
{"meta.traceId": "{{uuid}}"}

Ejemplo: cambiar solo user.status sin reescribir todo el body.

Método HTTP

Solo aplica cuando el trigger es HTTP.

GET: lectura
POST: alta
PATCH: actualización parcial
DELETE: eliminación

Ejemplo: GET /users/{id} para consultas y POST /orders para creación.

Trigger binding

Origen del evento cuando el trigger es EVENT.

Ejemplo: sqs:fluxy-mock-queue o kafka:orders.

Event target type

Destino donde se publica la respuesta del evento.

SQS: encola un mensaje
KAFKA: publica en un topic

Event target destination

Nombre o URL del destino según el tipo elegido.

Ejemplo SQS: http://localhost:4566/000000000000/orders-events

Ejemplo KAFKA: orders-events

Response description

Descripción opcional de la respuesta.

Ejemplo: Success response, Not found.

Response active

Marca si esa response compite para responder la request.

Ejemplo: dejar activa solo la variante 200 y desactivar la 404 temporalmente.

HTTP status

Código devuelto por la response.

200 OK
201 Created
404 Not Found
500 Internal Server Error

Latency (ms)

Retraso artificial antes de responder.

Ejemplo: 250 simula una API lenta.

Body template

Template de la respuesta.

{"id":"{{path.id}}","name":"John Doe"}
{"event":"ORDER_CREATED","orderId":"{{uuid:orderId}}"}

Ejemplo: usar {{path.id}} para reutilizar variables del path.

Response headers

Headers HTTP que acompañan la respuesta.

{"X-Mock":"true","Cache-Control":"no-store"}

Match headers

La response solo se usa si la request trae esos headers.

{"x-request-id":"123"}

Match query params

Valida parámetros de query exactos.

{"page":"2","status":"active"}

Match body contains

Busca un fragmento dentro del body entrante.

Ejemplo: "product" para detectar pedidos que incluyan ese campo.

Match path variables

Exige valores concretos para variables del path.

{"id":"42"}

Delay

Espera antes de ejecutar la post-action.

Ejemplo: 5000 para disparar la acción 5 segundos después de responder.

SQS queue URL

Destino de la post-action cuando publica en SQS.

Ejemplo: http://localhost:4566/000000000000/order-events

SQS message template

Template del mensaje enviado a la cola.

{"event":"ORDER_CREATED","orderId":"{{orderId}}"}
